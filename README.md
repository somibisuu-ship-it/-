# 랜선 투데이 투다리

밝은 U+ 매장과 따뜻한 투다리 술자리가 합쳐진 **최대 6인 실시간 2D 소셜 메타버스**입니다.
Node.js + Express + Socket.IO 서버가 방 상태를 관리하고, 같은 방의 모든 사용자에게 이동·채팅·술자리·건배·매장 상호작용을 실시간으로 동기화합니다.

## 실행

```bash
npm install
npm start          # http://localhost:3000 (Codespaces에서는 3000번 포트의 포워딩 URL)
```

| 명령 | 설명 |
| --- | --- |
| `npm run check` | 서버와 클라이언트 JS 전체 `node --check` |
| `npm test` | Socket.IO 프로토콜 및 아바타 렌더링 테스트: 입장/정원, 이동·술자리·취기·건배, 외형 호환성·눈·입술·실루엣·앵커 |
| `GET /health` | 상태 확인 (Railway 헬스체크) |

방 코드는 `MP1`, `MP2`, `MP3`이며 방마다 최대 6명입니다. `?room=MP2`로 초대 링크를 만들 수 있습니다. 로비에서 해당 방이 미리 선택되며, 저장된 캐릭터가 있어도 문 밖에서 **[들어가기] 확인 후** 입장합니다. 문 밖 이동은 로컬 상태로만 처리하며 정원을 차지하거나 방에 이동 이벤트를 보내지 않습니다.

## 조작

- **PC**: `W A S D` / 방향키 이동, 의자·매장 물건·출입문 가까이 가면 나타나는 버튼(또는 `E`/`Space`), `Enter`로 채팅 입력
- **모바일**: 왼쪽 아래 가상 조이스틱, 오른쪽 아래 상황별 버튼, 채팅은 `채팅` 버튼으로 접기/펼치기
- 좌석은 정확히 6개이며 의자 가까이 가면 **[앉기]**, 앉은 뒤에는 **[일어서기]**와 술자리 버튼(`술 고르기` `따라주기` `잔 들기` `마시기` `건배 제의`)이 나타납니다.

## 플레이 흐름

1. **로비**: 닉네임, 아바타(남/여), 헤어, 눈, 머리색, 유니폼, 액세서리 선택 → **[선택 완료 · 문 앞으로]** → 문 밖에서 이동 → 문 근처 **[들어가기]** → 확인 → `joinRoom`의 ack가 `ok`일 때만 매장 안쪽 시작점으로 입장합니다. 선택한 캐릭터는 `localStorage`(`tudariPlayerProfile`)에 닉네임과 아바타만 저장됩니다. 헤어 `hairStyle`은 A01~A04(숏컷/삐죽/슬릭/가르마, 반바지), B01~B04(보브/생머리/포니테일/웨이브, 테니스 스커트)이며 이전 `hair` 값도 읽습니다. 기존 머리색·색상 UI와 의상 ID/에셋 경로는 그대로입니다. 야구 유니폼은 화면 이름만 한글로 표시합니다.
2. **술자리**: 술 8종(소맥/연맥은 비율 조절), 따라주기(특정 사용자 또는 모두에게 → 대상 머리 위 ♥ 5초), 잔 들기, 마시기. 마신 횟수(`drinkCount`)로 취기가 올라갑니다 (0~4회 정상, 5~9회 1단계, 10~14회 2단계, 15회 이상 3단계: 홍조 → 눈 스프라이트 교체 → 빙글빙글 눈과 흔들림).
3. **건배**: 제의자가 건배사를 입력하고 `위하여!`로 시작 → 전원 잔 들기 대기 → 안내 → 제의자의 "위하여"는 **정확히 3번**(`[건배사] 위하여!` → `위하여.` → `위.하.여!`, 시간차 연출) → 참가자들이 각자 `위하여!`를 눌러 마십니다. 참가자의 `위하여!`는 3회에 포함되지 않습니다. 건배사에 "위하여"를 적어도 서버가 지워 총 횟수가 틀어지지 않습니다.
4. **매장 상호작용**: 휴대폰 두 곳과 TV에서 **[살펴보기]/[TV 보기]**. 내용은 [`public/shared/world.js`](public/shared/world.js)의 `STORE_INTERACTIONS` 배열에 있으며, 항목을 추가하면 새 직원 밈이 늘어납니다.
5. **출입문**: 넓어진 유리문 안쪽 근처 **[나가기]** → 확인 → `leaveRoom`(소켓 연결은 유지) → 같은 캐릭터로 문 밖에 돌아옵니다. 밖에서 문에 다가가면 **[들어가기]**가 표시되며 같은 모습으로 다시 입장할 수 있습니다. 밖의 상단 **[캐릭터 선택]**으로 로비에 돌아가 캐릭터나 방을 바꿀 수도 있습니다.
6. **직원**: 카운터 앞에서 **[말 걸기]** → 숙취해소제 받기. 서버가 `Math.round(drinkCount × 0.8)`로 정수화한 뒤 기존 5/10/15 취기 함수를 다시 사용합니다. 0잔일 때는 소비하지 않으며, 같은 Socket.IO 연결 세션에서 한 번만 받을 수 있습니다(로비 왕복·방 변경으로 재수령 불가, 새 연결은 새 세션). **숙취 -20%!** 말풍선이 3초 동안 동기화됩니다.
7. **감정**: 상단 😊/😂/😭/😡/❤️ → 머리 위에 미소/큰 웃음/흐르는 눈물/분노 표시/하트 도트 애니메이션이 2.6초 표시됩니다. 텍스트나 OS 이모지를 그리지 않고 픽셀 이미지와 움직임을 조합합니다. 서버 쿨다운은 0.9초이며 채팅·건배 말풍선과 별도 레이어입니다. 모바일 세로에서는 **[😊 감정]**을 한 번 눌러 펼칩니다.
8. **소리**: 직접 합성한 낮은 볼륨의 레트로 BGM과 행동별 효과음(Web Audio)을 사용합니다. 첫 터치/키 입력 뒤 재생되며 **배경음/효과음은 각각 독립적으로** 켜고 끕니다. `tudariBgmEnabled`, `tudariSfxEnabled`에 별도로 저장됩니다. 걷기 소리는 최소 320ms 간격입니다. 외부 음원이나 추가 패키지는 사용하지 않습니다.

## Socket.IO 이벤트

기존 이벤트 이름과 정규화 좌표(0~1) 프로토콜은 그대로 유지합니다.

| 클라이언트 → 서버 | 설명 |
| --- | --- |
| `joinRoom {room,name,avatar}` | ack `{ok,room,selfId,state}` / `ROOM_FULL`, `INVALID_CHANNEL`, `ALREADY_IN_CHANNEL` |
| `leaveRoom` | 좌석·잔·건배 참여 정리 후 방에서 나감 (연결 유지) |
| `move {x,y,dir}` | 서버가 속도와 충돌을 검증하고, 어긋나면 `playerMoved {snap:true}`로 되돌림 |
| `sit i` / `stand` | 의자 근처에서만 가능, 점유는 서버가 관리 |
| `chat text` | 모두에게 전달 + 머리 위 말풍선(약 3초) |
| `selectDrink {id,ratio}` | 술 선택 (예전 `{label}` 형식도 허용) |
| `pourDrink targetId \| 'all'` | 테이블에 앉은 다른 사용자에게만 가능 |
| `raiseGlass` / `drinkSip` | 잔 들기 토글 / 한 모금 |
| `cheersProposal {text}` | 건배 시작 (예전 `cheers`도 같은 흐름) |
| `cheersReady` / `cheersResponse` | 잔 들기 참여 / 제의자의 3번째 "위하여" 뒤 참가자 응답 |
| `interaction {id}` | 매장 물건 상호작용(구역 안에서만) |
| `staffInteraction {receive?:boolean}` | 직원 대화/수령. 서버가 거리·음주 횟수·연결 세션의 중복 수령 검증 |
| `emote kind` | `smile` / `laugh` / `cry` / `angry` / `heart`, 서버 쿨다운 적용 |

| 서버 → 클라이언트 | 설명 |
| --- | --- |
| `channelsState` | 방별 인원/정원 |
| `roomState {players,seats,cheers}` | 권위 있는 전체 상태. 플레이어마다 `glass` `drinkCount` `drunkLevel` `raisedGlass` 등, `cheers`에 `state` `initiator` `message` `raised` `responded` |
| `playerMoved` `bubble` `bubbleClear` `chat` `systemMessage` | 이동/말풍선/채팅/알림 |
| `heartEffect` `pourEffect` `playerAction` `interaction` | 연출용 이벤트 |
| `emote {id,kind,ms}` | 감정표현(전체 상태에도 남은 표시 시간 포함) |

## 구조

```
server.js                    Express + Socket.IO, 권위 있는 상태(방, 좌석, 술, 취기, 건배 상태머신)
public/index.html            로비 / 게임 / 팝업 마크업
public/style.css             도트 UI, 반응형(PC·모바일 세로/가로)
public/game.js               접속·상태 동기화·입력·카메라·렌더링
public/js/ui.js              로비, 채팅(스마트폰), 팝업
public/js/sprites.js         코드로 그리는 도트 아바타(파츠 레이어 + 에셋 슬롯)
public/js/props.js           테이블/의자/데크/출입문 등 장면 소품
public/js/audio.js           Web Audio BGM/행동 효과음, 개별 설정 저장
public/shared/world.js       서버와 클라이언트가 함께 쓰는 좌표, 충돌, 좌석, 매장 상호작용, 술, 건배 문구
public/assets/               제공 배경(uplus-tudari-space.png), 아바타 슬롯 manifest, 폰트
test/server.test.js          프로토콜 테스트
test/avatar.test.js          아바타 형태, 취기 중 외형 유지, 기존 값 호환성 테스트
```

좌표·충돌·좌석·상호작용·술 목록은 [`public/shared/world.js`](public/shared/world.js) 한 곳에서만 고칩니다. 서버와 브라우저가 같은 파일을 쓰므로 어긋나지 않습니다.

## 그래픽 에셋 교체

- 배경은 `public/assets/uplus-tudari-space.png`를 **수정하지 않고** 그대로 쓰며, 그 위에 소품과 아바타를 런타임에 얹습니다. 배경에 구워진 사람은 데크/바닥 보정/문 오버레이로 가려져 있습니다. 테이블 뒤 화분 두 개는 사용하지 않고, 원본의 빈 바닥에서 만든 `public/assets/table-floor-repair.png`를 합성합니다. 사람이 없는 배경으로 바꾸면 [`public/js/props.js`](public/js/props.js)의 `hasBakedPeople`을 `false`로 바꾸세요.
- 카운터 직원은 배경에 그려진 인물입니다. 보이는 상체 영역은 `(719,157)`에서 약 `62×88` 월드 픽셀이며 하체는 카운터에 가려져 있습니다. `STAFF.bounds`의 **실제 노출 높이 88px** / 아바타 기본 높이 46 아트 픽셀로 게임 렌더링 배율을 계산합니다. 헤어별 실제 높이는 약 84~90px입니다. 모바일에서도 같은 배율을 쓰며, 미리보기는 별도로 크게 유지합니다. 좌석에서는 의자 높이에 맞춰 위치만 보정하며 모든 포즈의 렌더링 배율은 동일합니다.
- 출입문 옆 칠판/카펫 문구는 소품 오버레이로 표시하고 원본 배경 파일은 바꾸지 않습니다. 하단 크레딧은 액션 버튼과 safe-area 밖에 별도로 배치합니다.
- 아바타는 `Base / Back Hair / Face / Eyebrows / Eyes / Front Hair / Top / Bottom / Shoes / Accessory / Hand Item` 레이어로 독립 관리됩니다. 손으로 그린 PNG/WebP로 바꾸려면 코드 수정 없이 [`public/assets/avatar/manifest.json`](public/assets/avatar/manifest.json)의 `slots`에 추가하면 됩니다.
  - 키: `${layer}/${variant}/${dir}-${action}-${frame}` (예: `top/uplus/down-walk-2`, `eyes/dizzy/down-idle-0`)
  - 이미지는 48×60, 발 사이 지면 앵커 (24, 54)에 1:1로 합성되고, 슬롯이 있는 레이어·프레임만 이미지로 바뀝니다. `left`는 `right`를 반전해 씁니다.
- 기본 도트는 큰 계단형 헤어 실루엣·넓고 낮은 눈·목 없이 연결된 작은 상의·짧은 팔다리로 그립니다. 머리/헤어는 기본 전체 높이의 약 61~63%이며, 큰 색면과 짧은 블록 하이라이트를 사용합니다. 기존 헤어 8종, 머리색 값, 의상 ID/대표 색과 48×60 프레임은 유지합니다.
- 눈 E01~E08은 큰 눈/동그란 눈/부드러운 눈/또렷한 눈/내려간 눈/올라간 눈/반달 눈/반쯤 감은 눈입니다. 선택창의 4×2 썸네일도 같은 눈·눈썹 렌더러를 씁니다. 기존 `round`, `smile`, `sleepy` 저장값은 유지하며, 취기 눈은 선택한 눈을 덮어쓰지 않습니다. A타입은 진한 눈썹·작은 입, B타입은 부드러운 눈썹·취기에도 유지되는 작은 빨간 입술을 사용합니다.
- 기존 안경·야구모자·리본·헤드셋에 `catEars`(고양이 귀), `bunnyEars`(토끼 귀), `crown`(미니 왕관), `starClip`(별 머리핀)을 추가합니다. 선택창은 같은 아바타 소스의 도트 썸네일로 비교하며, 장식은 착석/음주 때도 공통 머리 오프셋을 따라 프레임 안에 들어갑니다. 채팅/건배의 얼굴 초상 크기는 그대로입니다.
- 의상 화면 순서는 LG U+ 유니폼 → 기아 타이거즈 → 두산 베어스 → 삼성 라이온즈 → 엘지 트윈스 → 한화 이글스 → 캐주얼 의상 → 빈털털이입니다. 기존 의상 ID는 유지하며, 이전 흰 티 `basic` 프로필도 그대로 입을 수 있습니다. 새 `ragged`(빈털털이)는 패치·해진 소매/밑단이 있고 A타입은 헤진 반바지, B타입은 헤진 플리츠 스커트입니다.
- 좌우 옆모습은 눈·눈썹을 한 쪽만 표시합니다. 남녀는 같은 몸통 크기로 의상을 그려 로고와 등번호가 좁아지지 않으며, A/B 헤어에 따른 반바지·스커트 구분은 유지합니다. 선택창 미리보기는 4배율이고, 게임에서는 착석해도 서 있을 때보다 카메라가 확대되지 않습니다(작은 화면에서는 테이블을 담기 위한 축소만 허용).

## Railway 배포

배포 구성(`Dockerfile`, `railway.json`, `/health`, `PORT`)은 그대로입니다. **전체 플레이 테스트를 통과한 뒤에만 배포하세요.**

1. 저장소를 GitHub에 올리고 Railway에서 *Deploy from GitHub Repo*로 연결합니다.
2. 배포 후 Settings → Networking에서 Public Domain을 만듭니다.

## 참고

- 방 상태는 서버 메모리에 있어 서버가 재시작되면 초기화됩니다. 인스턴스를 여러 개로 늘리려면 Redis Adapter 같은 공용 상태 계층이 필요합니다.
- UI 폰트는 [갈무리11](https://github.com/quiple/galmuri)(SIL OFL 1.1)의 필요한 글리프만 담은 서브셋입니다. 라이선스는 `public/assets/fonts/Galmuri-OFL.txt`에 있습니다.
- 공개 서비스 전에는 이용약관, 개인정보 안내, 신고 및 차단 기능을 추가하세요.
